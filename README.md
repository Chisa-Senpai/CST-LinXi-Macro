# CST-LinXi-Macro

CST Studio Suite 本征模**慢波结构用户监视器**宏。挂载在本征模 `phase` 参数扫描任务上，
在每个扫描相位点自动提取本征模场数据，计算周期慢波结构的**归一化相速度**与**皮尔斯耦合阻抗**，
并自动生成**布里渊色散曲线**、**归一化相速度曲线**与**耦合阻抗曲线**。

- 许可证：[MIT](LICENSE)
- 支持平台：CST Studio Suite 2024 / 2025 / 2026（64 位）
- 当前版本：`v7.9.5.3 (Update 3)` —— 版本号来自 `LinXi.ini`，不在源码中硬编码

> 我是本项目的作者。下面的内容既是使用说明，也是我做这些设计取舍时的记录：
> 涉及你操作的步骤按「你」来写，涉及我的项目决策与版权归属的部分按「我」来写。

## 二、安装

**双击 `zh-CN v7.9.5 Update 3\双击我自动安装.bat` 即可**，无需手动复制文件。

脚本会自动完成：

1. 请求管理员权限（UAC 提权后自动继续）；
2. 从注册表探测已安装的 CST 版本，仅接受 **2024 及以上**；检测到多个版本时**全部安装，不再询问**；
3. 按下列方式部署文件：

| 源文件 | 目标位置 | 部署后名称 |
| --- | --- | --- |
| `MacroKit\LinXi.dll` | `<CST>\AMD64\` | `LinXi.dll` |
| `MacroKit\LinXi.ini` | `<CST>\AMD64\` | `LinXi.ini` |
| `MacroKit\LinXi.bas` | `<CST>\AMD64\` | `LinXi_Watch.bas` ← **监视器宏本体** |
| `MacroKit\LinXi.bas` | `…\Library\Macros\Admin LinXi Macro\` | `Run LinXi Macro.mcr` |
| `MacroKit\Me.bas` | 同上 | `Define LinXi Macro.mcr` |
| `MacroKit\She.bas` | 同上 | `Check LinXi Version.mcr` |

其中 `…\Library\Macros\` 指 `%APPDATA%\Dassault Systemes\CST STUDIO SUITE\Library\Macros\`。

`AMD64` 下的三个文件按检测到的每个 CST 版本**各部署一份**（屏幕上会依次打印
`[ k/n ] CST 安装根目录: …`）；用户宏目录与 CST 版本无关，只部署一次。

**关键设计**：监视器宏 `LinXi_Watch.bas` 与核心计算库 `LinXi.dll`、配置 `LinXi.ini`
放在同一个 `AMD64` 目录下。工程内的 `Model.pfc` 由 `Define LinXi Macro` 宏在添加监视器时
**按需复制**，安装脚本不会向任何工程目录写入文件。

卸载：运行 `双击我自动卸载.bat`。它会删除所有 2024 及以上版本 `AMD64` 下的三个文件，并**整体删除
`Admin LinXi Macro` 目录**，因此无需逐文件清理。

> 卸载脚本**不会触碰你的工程**。

> ⚠️ **路径不能包含括号**。工程本身也建议放在短路径下（Windows 260 字符限制）。

## 三、使用

1. 启动 CST，打开本征模工程（慢波结构已设置周期边界）；
2. 在**宏命令**中添加 `Define LinXi Macro`（对应 `Admin LinXi Macro` 菜单）；
3. 弹出参数设置向导，按四步确认：
   - **第一步**：选择参与计算的模式（全部 / 勾选 / 自定义如 `1,3,5`）；
   - **第二步**：设置耦合阻抗参考位置（周期方向自动锁定为计算域中心）；
   - **第三步**：选择功率流算法 —— **间接法**（由 E、H 场计算）或**原生法**（用 CST 生成的功率流场）；
   - **第四步**：选择需要计算耦合阻抗的**区域** —— **行波区**（要求频率随 `phase` 上升）、
     **返波区**（要求频率随 `phase` 下降）或**两者都计算**（不判断频率升降，所有扫描点都参与计算）；
4. 确认后即可直接启动 `phase` 参数扫描，**无需修改任何代码**；
5. 扫描结束后，结果出现在 `1D Results\User-Defined Macro Result\` 下。
   如需随时核对版本，运行宏 `Check LinXi Version`。

> 无论选择哪个区域，**π 整数倍点**以及**频率连续 5 个扫描点完全不变**（相位差没有真正加到周期边界上）
> 这两类无效扫描点都不会参与耦合阻抗计算。

安装是否成功的判据：首次运行时 CST 消息窗口出现
`核心计算库 LinXi.dll 加载成功 v122`（版本号随 DLL 实际版本变化）。

### 宏写入的工程参数

| 参数 | 含义 |
| --- | --- |
| `Macro_SweepWatch_Enable` | 运行使能位，写作 `整数位.小数位`：整数位 = 功率流方式，小数位 = 计算区域 |
| ↳ 整数位 | `1` = 间接功率流法，`2` = 原生功率流法，`0` = 禁用 |
| ↳ 小数位 | `0` = 行波区 + 返波区，`1` = 仅行波区，`2` = 仅返波区 |
| ↳ 合法取值 | `1.0` `1.1` `1.2` `2.0` `2.1` `2.2`；其它取值（如 `1.3`、`1.11`、`3.0`）会在下一次运行时重新弹出向导 |
| `Kc_RefPos_x` / `y` / `z` | 耦合阻抗参考位置坐标（周期方向为计算域中心，不可改） |
| `Macro_Modex` | 模式 `x` 的耦合阻抗计算标志。**宏只判断该参数是否存在，不看取值** |

`1.0` / `2.0` 表示"行波区与返波区都计算"。旧工程里由 Update 2 写下的整数 `1` / `2`
按同样规则解释为 `1.0` / `2.0`，即升级后会多算返波区；只想计算行波区时，
删除 `Macro_SweepWatch_Enable` 让向导重新弹出并选择 `1.1` / `2.1` 即可。

删除 `Macro_SweepWatch_Enable`（或 `Kc_RefPos_*`、`Macro_Mode*`）即可让向导在下次运行时重新弹出。

> 这四个参数**不得加入扫描变量**，否则会破坏宏的运行状态判断。

## 四、扫描期间的注意事项

宏在运行时会频繁读写 CST 界面数据，任何人为操作都可能与它“抢夺控制权”，导致读场失败。

- **扫参期间不要操作 CST 窗口**；
- 建议**单独开一个 CST 窗口**跑本征模扫描；
- **切勿在同一窗口内并行运行多个本征模扫参任务**；
- 扫参前确认电场结果已就绪；
- 不要打开本征模工程下 E/H 的 `Fields on Plane`、`Cutting Plane` 视图；
- **重复扫参前请先清除已有结果**，否则上一次的结果可能丢失；
- 求解器推荐六面体 **JDM** 算法（精度更高）；JDM 下本征模名称不得含小数点。

## 五、结果判读

| 曲线 | 结果树位置 | 说明 |
| --- | --- | --- |
| 布里渊图（β–f） | `Brillouin Diagram Beta` | 曲线应平滑连续，无跳变或断点 |
| 布里渊图（phase–f） | `Brillouin Diagram Phase` | 扫描相位与频率的关系 |
| 归一化相速度 vp/c | `Normalized Phase Velocity` | 应随频率呈合理趋势 |
| 皮尔斯耦合阻抗 Kc | `Pierce Interaction Impedance` | 有效点数常少于 β 曲线点数：无效点与不符合所选计算区域的点会被跳过，属正常 |

连续多点出现 `0` 值形成的断崖、尖峰或不连续曲线，称为**畸形曲线**，绝大多数由**读场失败**引起。

> 选择「仅计算行波区」或「仅计算返波区」时，只有频率变化方向符合要求的扫描点会出现在 Kc 曲线上，
> 曲线点数自然少于布里渊曲线；选择「行波区和返波区」则除无效点外全部扫描点都会参与计算。

## 六、故障排查

宏的完整运行日志写在**工程目录** `Temp\_macro_log.txt`（超过 5 MB 自动滚动为 `*.bak`），
CST 消息窗口同时会显示带 `MacroMsg [INFO] / [WARN] / [ERROR] / [CRIT]` 前缀的摘要。

| 现象 | 原因与处理 |
| --- | --- |
| 提示找不到配置文件 / 8 个键不齐 | `LinXi.ini` 缺失或被改成了 **UTF-8**。该文件必须保存为 **ANSI/GBK**；重新运行安装脚本可恢复 |
| DLL 加载失败 / 版本过旧 | `LinXi.dll` 未部署、被换成 32 位版本，或版本低于 `LinXi.ini` 里的 `DllMinVersion`；重新安装 |
| 畸形曲线 | 多为读场失败：扫参期间操作了界面、同窗口多任务，或机器快慢导致延时失配。可调大 `LinXi.bas` 中的 `WAIT_SEC`；对 0 值区间局部重扫 |
| 日志出现「频率未随 phase 变化」并判定扫描无效 | 求解器没有把 `phase` 施加到周期边界的相位差上。检查：① 该方向两侧边界是否都设为 periodic；② 相位差是否绑定到扫描变量 `phase`；③ 计算域是否恰好为一个周期 |
| 日志出现「频率未上升」 | 当前选择的是**仅计算行波区**，而该扫描点的频率没有随 `phase` 上升，宏按约定跳过该点的耦合阻抗计算（只记录频率与相位）。若这些点本应参与计算，请在向导中改选返波区或"行波区和返波区" |
| 日志出现「频率未下降」 | 当前选择的是**仅计算返波区**，而该扫描点的频率没有随 `phase` 下降，同样被跳过。处理方式同上 |
| 每次运行都弹出参数设置向导 | `Macro_SweepWatch_Enable` 的取值不是 `1.0` `1.1` `1.2` `2.0` `2.1` `2.2`（例如被改成了 `1.3`、`1.11`），或该参数被删除。重新在向导中选择即可，宏会把合法取值写回参数表 |
| 临时文件写入失败 / 路径过长 | 工程路径过深，超出 Windows 260 字符限制。把工程移到更短的目录 |

## 七、二次开发

- 源码为 CST 内嵌 VBA（`.bas`），编码为 **ANSI/GBK**，换行 **CRLF**。修改时请保持这两点，否则 CST 会读不出中文或键值。
- 中文版 `.bas` 带完整中文注释，用**行尾单引号**书写。
- **英文版 `.bas` 已去除全部注释**，只保留文件头的 MIT 版权声明块（MIT 要求保留版权与许可声明）。
- 两版的 `LinXi.bas` 都把可调常量（`WAIT_SEC`、`MAX_FREQ_RETRY`、`FREQ_FLAT_*`、`KC_SANITY_MAX`、`MAX_PATH_SAFE` 等）集中放在文件开头，便于按机器性能调整。
- 使能位 `Macro_SweepWatch_Enable` 的编码集中在文件开头的 `PW_SRC_*` / `REGION_*` 常量与 `DecodeEnableFlag` 函数中；
  功率流方式用整数位、计算区域用一位小数位。新增区域时只需扩展这套编码与 `RegionText`。
- 两版的判断逻辑必须保持一致：以后修改 `LinXi.bas` 时请同步改动中文版与英文版（英文版不写注释）。
- `LinXi.dll` 同样是我的原创作品并以 MIT 发布，但我**当前只提供预编译二进制、未公开编译源码**，因此使用者无法自行修改或重新编译其内部逻辑；其导出函数原型见 `LinXi.bas` 顶部的 `Declare Function` 声明块。详见 [NOTICE](NOTICE)。
- 当前无自动化测试：改动后请在 CST 中用一个小规模模型跑一遍完整 `phase` 扫描，并核对日志与曲线。

## 八、更新日志

### Update 3 — `v7.9.5.3`（2026-09-23）

- 参数设置向导新增**第四步**：选择计算耦合阻抗的**区域**。
  - **行波区和返波区**：不判断频率随 `phase` 的升降，所有扫描点都计算耦合阻抗；
  - **仅行波区**：只计算频率随 `phase` 上升的扫描点，频率下降的点跳过；
  - **仅返波区**：只计算频率随 `phase` 下降的扫描点，频率上升的点跳过；
  - 界面只为**当前选中**的那一项显示说明文字，其余两项的说明隐藏。
- `Macro_SweepWatch_Enable` 从整数扩展为**整数位 + 一位小数位**：整数位选功率流方式，小数位选计算区域；
  取值非法（如 `1.3`、`1.11`）时下一次运行会重新弹出向导，而不是直接中止。
  旧工程里的 `1` / `2` 按 `1.0` / `2.0` 解释，即"两个区域都计算"。
- 新增/调整日志：扫描结束时打印本次的功率流方式与计算区域，方向不符的点单独给出提示。
- **使用帮助**对话框加大纵向行距（行距 22 → 28），说明文字未作任何改动；对话框高度 540 → 645。
- 安装脚本不再让用户挑选 CST 版本：检测到几个 2024 及以上的版本就**全部安装**；用户宏目录只部署一次。
- 英文版同步以上全部改动（保持无注释风格）；两份 README 更新到本版本。
